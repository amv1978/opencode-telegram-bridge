# Telegram

## Первый запуск

1. Создайте бота у **@BotFather**, скопируйте токен.
2. Вставьте токен в панель `http://127.0.0.1:7788` → **Сохранить**.
3. Напишите боту `/start` в личку. Если allowlist пуст, первый пользователь
   становится **администратором**; остальным бот отвечает «Нет доступа».

Дальше доступ выдаётся только явным добавлением ID в `telegram.allowedUsers`
(роль `admin` или `user`).

## Режимы

| Режим | Поведение |
|---|---|
| `private` | Личные чаты, одна активная сессия на чат |
| `topics` | Форум-супергруппа, тема = сессия |
| `both` | И то и другое (по умолчанию) |

Группы подключаются только явно: сообщения из любой группы, кроме `topicsChatId`,
игнорируются. Исключение — администратор с `/chatid` в новой форум-группе.

## Форум-группа

1. Создайте группу, включите **Темы** (Topics).
2. Добавьте бота администратором с правом **Управление темами**.
3. Отправьте в группе `/chatid` — бот сохранит `topicsChatId`.
   Вручную: поле «ID форум-группы» в панели.
4. Создание темы сразу создаёт сессию OpenCode с названием темы (если у темы ещё
   нет привязки). Бот отвечает в теме короткой цитатой «🆕 Сессия создана».
   Первое сообщение в уже существующей теме без привязки тоже создаёт сессию —
   по тексту сообщения.
5. Сообщение в **общем чате** группы создаёт отдельную тему с названием задачи
   (`autoTopics`, по умолчанию включено). Общий чат никогда не является адресом
   для ответов: только темы.

Закрытие или удаление темы не завершает сессию OpenCode. Если тема удалена,
привязка очищается, а финальный ответ уходит в корень чата.

## Команды

| Команда | Действие |
|---|---|
| `/start`, `/help` | Приветствие, роль, список команд |
| `/new [папка]` | Создать сессию и привязать к чату/теме |
| `/sessions [поиск]` | Последние сессии кнопками; в форуме открывает тему |
| `/attach <id\|префикс>` | Подключить существующую сессию |
| `/topic <название>` | Создать тему форума и сессию |
| `/detach` | Отвязать чат или тему от сессии |
| `/chatid` | ID чата, тип, признак форума; админ сохраняет группу |
| `/status` | Название, id, папка, модель, агент, занятость, стоимость |
| `/model [provider/id]` | Показать или сменить модель |
| `/agent [id]` | Список агентов или смена агента |
| `/stop` | Прервать текущий ход |
| `/fmt` | Проверка rich-разметки |

## Статус хода и футер

Пока ход выполняется, над ответом показывается живой блок:

```
🟢 **DeepSeek V4.1 Flash** · thinking… 42s
🛠 edit bot.ts · 3s ✓
🔍 grep "permission" · 1s ✓

<текст ответа…>
```

- Имя модели берётся из `session.model` и `/api/model` (`name`); если имени нет —
  `providerID/id`, иначе `OpenCode`.
- Каждая строка статуса — отдельная физическая строка, склеивания нет; жирным
  выделено только имя модели, остальные подписи очищаются от `*`/`_` и режутся
  до 60 символов. Слово `tool` в подписи не выводится — только имя и аргумент.
- Статус обновляется независимым тикером раз в 1.2 с, пока есть активные
  инструменты или субагенты; текстовые дельты для этого не нужны.
- Инструменты: `session.tool.called` → иконка + имя + короткий аргумент,
  `session.tool.success` → `✓`, `session.tool.failed` → `✗`. Показываются
  последние 2 строки; завершённые исчезают через ~10 с; повторы схлопываются
  (`edit bot.ts ×3`). При `showTools = "off"` блок инструментов скрыт.
- Субагенты: дочерняя сессия (`parentID`) не открывает отдельный стрим, а
  добавляет строку в живой блок родителя — `🧩 explore · 12s`, после
  завершения `✓`/`✗` (`🧩 general · 1m 03s ✓`). Видно последние 2 строки,
  одинаковые агенты схлопываются (`×2`), завершённые скрываются через ~10 с,
  при конце хода родителя — вместе с блоком. `session.synthetic` с отчётом
  ребёнка публикуется в чат цитатой `> 🧩 <агент>: …` (первые ~300 символов).
  Отключается флагом `showSubagents: false`.
- Когда ход завершается, блок исчезает целиком, а под ответом через пустую
  строку остаётся одна курсивная строка:

```
_DeepSeek V4.1 Flash · ⏱ 1m 23s · ⚡ 197.8 tok/s · 🧠 531k_
```

Для `interrupted`/`failed`: `_… · ⏹ остановлено · ⏱ 42s_` /
`_… · ⚠️ ошибка · ⏱ 42s_`. Числа считаются по прежней формуле OpenCode
(duration, tok/s, context) и не меняются.

## Права

Запрос `permission.asked` приходит сообщением с кнопками:

- **✅ Разрешить** — `once`;
- **♾ Всегда** — `always`;
- **⛔️ Отклонить** — `reject`.

Запрос живёт 15 минут; просроченная кнопка отвечает «Запрос истёк». Несколько
запросов хранятся независимо (ключ в callback data).

## Эхо-защита

Мост зеркалит prompt, набранный в Desktop/TUI, в привязанный чат (цитатой).
Чтобы это сообщение не ушло обратно в модель, текст запоминается на 10 минут
(последние 20 на чат) и при совпадении игнорируется. Промпты с
`metadata.source = "telegram"` не зеркалятся вовсе.

## Медиа и голос

- Фото и документы до **20 МБ** (лимит Bot API на скачивание) уходят в сессию
  как data-URI; подпись становится текстом задачи.
- Голосовые и аудио (OGG/Opus, MPEG, WAV, MP4, WebM) распознаются локально,
  см. [voice.md](voice.md). Расшифровка приходит rich-сообщением в стиле
  зеркальных сообщений: цитата `> 💠 **Расшифровка · голос**`, текст построчно
  и время обработки `⏱ … с`; если rich-режим недоступен — обычным текстом.
- Видео, стикеры, гифки не поддерживаются — бот сообщает об этом.

## Форматирование

Ответы отправляются как **rich messages** с нативным Markdown: заголовки, списки,
таблицы, код. Если Telegram отклоняет rich-режим, мост навсегда переключается на
HTML (`parse_mode: "HTML"`): жирный, курсив, ссылки, `<pre>`; таблицы рендерятся
как `<pre>`. MarkdownV2 не используется — слишком хрупкое экранирование.

Длинный ответ делится на части: 30 000 символов для Markdown и 3800 для HTML;
блоки кода закрываются и открываются заново на границе частей.

## Ограничения Bot API

- Нет подтверждений прочтения и статуса «печатает» на стороне получателя;
  `sendChatAction("typing")` лишь показывает «печатает…», пока идёт ход.
- Бот не может писать первым в личку: пользователь должен нажать `/start`.
- Бот не может отправлять сообщения от имени человека и читать историю чата.
- В группе бот получает сообщения либо как администратор, либо с выключенным
  privacy mode (BotFather → `/setprivacy` → Disable, затем пере-добавить в группу).
- Правки ограничены частотой: при 429 мост ждёт `retry_after` и повторяет.
- Скачать файл больше 20 МБ бот не может — это ограничение Telegram, не моста.
