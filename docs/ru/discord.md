# Discord

Второй транспорт рядом с Telegram: те же сессии OpenCode, но в публичных тредах
Discord. Telegram-код не меняется, оба транспорта могут работать одновременно.

## 1. Приложение в Discord Developer Portal

1. <https://discord.com/developers/applications> → **New Application**.
2. **Bot** → **Add Bot** → скопируйте **Token** (показывается один раз).
3. **Bot → Privileged Gateway Intents** → включите **MESSAGE_CONTENT**.
   Без него бот не видит текст обычных сообщений (slash-команды работают).
4. **Installation** (или OAuth2 → URL Generator):
   - scopes: `bot`, `applications.commands`;
   - права: `View Channels`, `Send Messages`, `Create Public Threads`,
     `Send Messages in Threads`, `Read Message History`, `Attach Files`;
   - `Manage Threads` — по желанию (переименование тредов при `session.renamed`).

Готовая ссылка-приглашение (подставьте `CLIENT_ID`):

```
https://discord.com/api/oauth2/authorize?client_id=CLIENT_ID&permissions=309237746688&scope=bot%20applications.commands
```

(`309237746688` — просмотр каналов, отправка сообщений, создание публичных
тредов, сообщения в тредах, история, вложения. С `Manage Threads`:
`326417615872`.)

## 2. Настройка моста

В веб-панели `http://127.0.0.1:7788` → **Настройки → Discord**:

| Поле | Значение |
|---|---|
| Включить Discord | чекбокс |
| Токен бота Discord | токен из Dev Portal; пустое поле = не менять сохранённый |
| ID серверов | snowflake через запятую; пусто = бот игнорирует всё |
| ID пользователей | кто может управлять ботом; пусто = никто |

Токен хранится только в `%APPDATA%\opencode-telegram-bridge\config.json`,
никогда не пишется в лог. В панели видны только последние 4 символа (`…abcd`).

Те же поля можно задать в `config.json`:

```json
{
  "discord": {
    "enabled": true,
    "token": "…",
    "allowedGuilds": ["123456789012345678"],
    "allowedUsers": ["123456789012345678"],
    "mode": "threads"
  }
}
```

ID пользователя: Discord → Настройки → Дополнительно → Режим разработчика,
затем правый клик по себе → «Копировать ID».

## 3. Команды

Команды регистрируются отдельно в каждом разрешённом сервере при подключении.

| Команда | Что делает |
|---|---|
| `/help` | справка |
| `/new [title]` | новая сессия + публичный тред, имя = title или `Discord session` |
| `/sessions` | последние 10 сессий |
| `/attach <sessionID\|prefix>` | подключить существующую сессию к текущему треду |
| `/detach` | отвязать тред/канал (сессия в OpenCode остаётся) |
| `/stop` | прервать выполнение |
| `/status` | модель, агент, каталог, стоимость, версия моста |
| `/model [provider/id]` | показать/сменить модель |
| `/agent [id]` | показать список/сменить агента |
| `/observe [action]` | зеркало запусков Desktop/TUI в этот канал/тред (`on`, `off`, `status`; без аргумента — переключить) |
| `/budget` | лимиты стоимости и расход за день |
| `/fmt` | проверка форматирования |

## 4. Модель тредов

- Одна сессия OpenCode = один **публичный тред**.
- `/new` создаёт сессию с каталогом `defaultDirectory` и тред в текущем канале.
- Сообщение в треде, привязанном к сессии, уходит в `oc.prompt(..., {source:"discord"})`.
- Сообщение в непривязанном треде привязывает его к новой сессии; заголовок —
  первые 60 символов текста.
- Сообщение в обычном канале создаёт тред из этого сообщения и привязывает к нему.
- Удаление/закрытие треда не завершает сессию; привязка очищается, следующее
  сообщение создаст новую сессию.

## 5. Поведение

- **Таблицы**: узкие (≤4 колонок и ≤72 символов по ширине) идут блоком
  кода с переносом ячеек по словам (каждая колонка ≤32 символов). Широкие
  таблицы превращаются в список `**Заголовки**` + строки
  `- Колонка: значение · …`, чтобы не было горизонтальной прокрутки.
- **Слэш-команды**: подтверждение (`deferReply`) уходит сразу, ответ —
  `editReply`. Просроченная интеракция (10062) логируется, а не бросает
  исключение. При обрыве gateway логин/реконнект повторяется с backoff
  5 с → 5 мин, мост перезапускать не нужно.
- **Живой статус**: над ответом в том же сообщении — физические строки
  `🟢 **<Модель>** · thinking. 42s`, затем до двух последних инструментов вида
  `⠋ 🛠 edit bot.ts · 3s` → `🛠 edit bot.ts · 3s ✓`. Жирная только модель;
  подписи без `*`/`_` и не длиннее 60 символов, слово `tool` не выводится.
  Статус обновляется независимым тикером раз в 2.5 с (без текстовых дельт);
  этот же тик двигает спиннер и точки `thinking.`, порядок строк стабилен,
  сообщение правится на месте. Повторы схлопываются (`×3`), завершённые строки
  скрываются через ~10 с, при завершении хода блок удаляется.
- **Статус в заголовке**: у тредов Discord нет иконок, поэтому индикаторы
  **по умолчанию выключены**. Включить можно через `discord.titleStatus: "rename"`:
  тред переименовывается в `⏳ <название>` на старте хода и в `✅ <название>` при
  успехе, затем через ~10 с возвращается исходное название. Discord разрешает
  около двух переименований за 10 минут, поэтому новое переименование делается
  только через 5 минут после предыдущего: короткий ход может оставить `⏳` до
  открытия окна, после чего название восстановится. Переименование сессии на ходу
  сохраняет маркер и становится новым исходным названием. `ui.titleStatus`
  относится только к Telegram.
- **Субагенты**: дочерняя сессия (`parentID`) не открывает отдельный тред. При
  живом блоке родителя она добавляет строку — `🧩 explore · 12s`, затем `✓`/`✗`
  (`🧩 general · 1m 03s ✓`). Максимум 2 строки, повторы схлопываются (`×2`),
  завершённые скрываются через ~10 с (правки с тем же лимитом 2.5 с). Если ответ
  родителя уже завершён, отправляется отдельное сообщение
  `🧩 <агент> · <title> · 0m 12s`, оно правится каждые ~2.5 с и заканчивается
  `✅`/`✗`; удаляется через 10 минут, если на него не ответить. Не больше 3
  отдельных карточек; лишние дети идут в одно сообщение до 3 строк. Отчёт
  ребёнка (`session.synthetic`) уходит цитатой `> 🧩 <агент>: …` (первые ~300
  символов). `showSubagents`: `auto` (по умолчанию), `inline`, `message`, `off`;
  булевы значения — `auto`/`off`.
- **Стриминг**: одно сообщение-заглушка, правки не чаще раза в 2.5 с (лимит
  Discord); перед нарезкой текст проходит через `toDiscordMarkdown`: узкие
  таблицы — выровненный блок кода, широкие — список, `####`–`######` — жирным
  (`#`–`###` остаются заголовками). Остальная разметка не меняется, код в ``` не трогается.
  Текст режется на куски по 1900 символов, лишние куски уходят новыми
  сообщениями; блок кода не разрывается — на границе он закрывается и
  открывается заново с тем же языком.
- **Финал**: строка статистики
  `<Модель> · ⏱ <duration> · ⚡ <tok/s> · 🧠 <context>`. Модель — из
  последнего assistant-сообщения, имя — из `/api/model` (та же карта, что в
  Telegram). Формула duration/tok/s/context — как в Telegram (`turnStats`).
  При аварийном конце причина идёт строкой выше, а статистика остаётся
  последней: `⚠️ остановлено: /stop`, `⛔ бюджет: $X из $Y`, `⚠️ лимит шагов`,
  `⚠️ ошибка: <коротко>`; заблокированные вызовы считаются
  (`· 2 инструмента заблокировано`). Та же причина пишется в лог.
- **`/observe`**: зеркалирует запуски из Desktop/TUI в текущий тред или канал.
  Живая карточка (`👀 название · модель`, `⏱ … · 🛠 N`) правится раз в 2,5 с;
  финальная добавляет `✅`/`⚠️`, длительность, tok/s, контекст и стоимость хода.
  Сессии, привязанные к треду/каналу или уже имеющие активный стрим,
  пропускаются. Флаг и наблюдаемые сессии хранятся в `state.json` (`observe`);
  `/observe off` очищает, `/observe status` показывает список.
- **Файлы агента**: части `type:"file"` и `tool.state.content` публикуются
  вложениями Discord до 10 МБ с именем файла; больше — ссылкой. Кэш хэшей relay
  исключает повторную отправку между транспортами.
- **Разрешения**: `permission.asked` → сообщение с кнопками
  «Разрешить / Всегда / Отклонить», TTL 15 минут.
- **Формы**: `form.created` (`question`, `mcp-elicitation`, `websearch.provider`)
  публикуется одним сообщением: заголовок, `1/2 · Поле`, дальше
  - до 5 вариантов — кнопки, 6–25 — `StringSelectMenu`, больше 25 — кнопки
    страницами по 15;
  - мультивыбор — меню (`min`/`max` значений) или переключение кнопками и
    подтверждение **✅ Готово**;
  - логическое поле → `✅ Да` / `❌ Нет`; текстовые/числовые поля и
    **✍️ Свой ответ** открывают **модальное окно** (свободный текст, без
    состояния «ждём сообщение»);
  - **⏭ Пропустить** для необязательных полей, **✖️ Отменить** вызывает
    `DELETE …/form/{id}?message=Отменено в Discord`.

  Ответы уходят в `POST /api/session/{id}/form/{formID}/reply` типизированными
  значениями; сообщение становится `✅ Ответ отправлен` с выбранными подписями
  и теряет компоненты. TTL 15 минут («Форма устарела — ответьте в OpenCode»);
  `form.replied`/`form.cancelled` из Desktop/TUI закрывают сообщение, а опрос
  привязанных сессий раз в 20 с ловит формы с потерянным эфемерным событием.
- **Вложения** (изображения и документы ≤ 20 МБ) скачиваются и уходят в сессию
  как `files: [{uri: "data:…", name}]`.
- **Голос/аудио**: скачивается, распознаётся через HEX (`transcribeAudio`),
  в тред приходит одна цитата `> 💠 **Расшифровка · голос**` с текстом и
  `> ⏱ <secs> с`; заголовок сразу переходит в текст, пустых строк `>` нет
  (Discord показывает их литералом). Существующие `>` в тексте снимаются,
  поэтому двойных `> >` не бывает. Затем текст уходит в промпт.
- **Зеркало**: промпты из TUI/Desktop (`session.inbox.enqueued` без
  `metadata.source === "discord"`) публикуются в треде цитатой с `👤`.
- **Субагенты** показываются строками `🧩` в блоке родителя, отдельными
  карточками, если ответ уже завершён, и цитатой с отчётом; отдельного треда для
  дочерней сессии нет.

## 6. Ограничения Discord

- 2000 символов на сообщение; мост режет на 1900.
- Нет нативных таблиц: перед отправкой они превращаются в выровненный блок
  кода (ячейки дополняются пробелами, разделитель `---` сохраняется).
- 15 минут — TTL кнопок разрешений; после этого запрос нужно повторить в OpenCode.
- Вложения больше 20 МБ пропускаются (ограничение загрузки бота).
- `mode` в v1 — только `threads`.
- Требуется включённый привилегированный intent **MESSAGE_CONTENT**.

## 7. Диагностика

- `discord: allowedGuilds is empty` — заполните ID серверов.
- `discord: allowedUsers is empty` — заполните ID пользователей.
- `Used disallowed intents` — включите MESSAGE_CONTENT в Dev Portal.
- `Unknown Guild` при регистрации команд — бот не приглашён на этот сервер.
- Сообщения в лог: `%APPDATA%\opencode-telegram-bridge\bridge.log`.
