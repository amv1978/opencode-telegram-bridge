# Автообновление (Windows)

Мост проверяет GitHub Releases и обновляется из portable-**bundle** без мастера
установки. Данные в `%APPDATA%\opencode-telegram-bridge\` (`config.json`,
`state.json`, привязки, токены) не трогаются.

## Поиск порта

Веб-UI может занять `7788+N`, если настроенный порт занят, поэтому сразу после
запуска сервера мост пишет `%APPDATA%\opencode-telegram-bridge\port.json`
(`port`, `pid`, `version`, `startedAt`). Оболочка Electron сначала проверяет этот
порт, затем `OCBRIDGE_PORT`, затем 7788..7797, и запускает мост с
`--port <n>`. При чистом выходе файл удаляется; устаревший файл безопасен —
оболочка всегда проверяет `/api/state`. `--port 7790` (`--port=7790`) заменяет
порт из конфига на один запуск.

## Как это работает

1. `GET https://api.github.com/repos/amv1978/opencode-telegram-bridge/releases/latest`
   (публично, без токена). Запрос идёт через тот же прокси/pinned-транспорт, что и
   Telegram (если настроен), иначе через `HTTPS_PROXY`, иначе напрямую.
2. `tag_name` сравнивается с `package.json` (префикс `v` и суффиксы сборки
   игнорируются).
3. Находятся файлы релиза `ocbridge-bundle-*.zip` и
   `ocbridge-bundle-*.zip.sha256`. Файл `.sha256` может содержать только хеш
   (или `<hash>  <имя>`).
4. При старте (и по умолчанию каждые 6 часов) проверка идёт в фоне. Результат
   кэшируется в `state.json` (поле `update`), панель сразу показывает последнюю
   известную версию после перезапуска. Таймаут проверки — 20 с; сетевые ошибки и
   ответы 5xx повторяются через 5 с, 30 с и 5 мин.

Автообновление работает **только для собранного `ocbridge.exe`**. В dev-режиме
(`bun run src/index.ts`) обновление недоступно.

## Загрузка

- Куда: `%TEMP%\ocbridge-update\bundle.zip` (файл `.part` сохраняется между
  запусками).
- Прогресс 0–100 % виден в `/api/state`, панели и подсказке трея.
- При `update.autoDownload` (по умолчанию **true**) найденное обновление
  скачивается в фоне: при старте, при обнаружении и по таймеру. Пока идёт ход,
  загрузка встаёт на паузу между блоками и продолжается после его конца.
- Порядок загрузки: **BITS** (`Start-BitsTransfer`) → **curl.exe** с `-C -` →
  встроенный `fetch` с `Range`. Любой транспорт докачивает `.part`, а не
  начинает заново. Вся загрузка ограничена 30 минутами и отменяется кнопкой
  «Отмена» (`.part` остаётся для повтора).
- Опубликованный `.sha256` обязателен: отсутствие или несовпадение хеша
  отменяет обновление и оставляет текущую версию.

## Ошибки

У каждой ошибки есть машинный код, HTTP-статус (если был) и понятный текст:

| Код | Значение | Что видит пользователь |
|---|---|---|
| `network` | нет связи с GitHub | «Нет сети или GitHub недоступен» + подсказка про прокси |
| `rate-limit` | HTTP 403/429 | «GitHub ограничил частоту запросов» + время сброса |
| `hash` | несовпадение SHA256 | «SHA256 не совпал — обновление отменено» |
| `write` | нет прав на запись | «Нет прав на запись в папку установки» |
| `asset` | в релизе нет bundle/sha | «Обновитесь через установщик» |

`/api/update/*` возвращает `200` только при успехе, иначе `429`, `502`, `409`,
`404`, `400` или `500`. Панель показывает `update.error` в баннере и тосте;
«Проверить обновления» никогда не сообщает об успехе при ошибке. Ошибки загрузки
и установки также уходят в личный чат администратора (тот же адрес, что у
уведомлений о жизненном цикле), не чаще одного раза в 10 минут.

## Установка и откат

1. Zip распаковывается в `{app}\new` (каталог с `ocbridge.exe`, обычно
   `%LOCALAPPDATA%\Programs\OpenCodeTelegramBridge`).
2. `prevVersion` записывается в `state.json`, в чат уходит
   `🔄 обновлено с X до Y — перезапускаюсь`.
3. Отдельный PowerShell-помощник ждёт выхода моста, переносит текущий layout в
   `{app}\prev` (хранится только одна предыдущая версия), перемещает `new` в
   `{app}` и запускает desktop-оболочку (или `ocbridge.exe --no-browser`).
4. Health-check: `GET http://127.0.0.1:<фактический порт веб-UI>/api/state`
   каждую секунду до 60 с. Порт берётся тот, который реально занял веб-сервер
   (он может отличаться от настроенного, если порт был занят). При ошибке
   помощник останавливает новую версию, возвращает `prev` и запускает её; откат
   тоже проверяет health и при неудаче пишет `rollback-health.txt`. Сломанный
   layout удаляется.
5. После успешного перезапуска приходит обычное уведомление о старте.

Обновление никогда не перезаписывает `config.json`: заменяются только
`ocbridge.exe`, `ffmpeg.exe`, `ocbridge-cli.exe`, `desktop\`, `version.json`,
`CHANGELOG.md` и `README.md`, поэтому `telegram.*` и `discord.*` (токены, прокси,
списки серверов) сохраняются.

`ocbridge-cli update --rollback` (или пункт трея «Откатиться на X») сразу
возвращает `{app}\prev`; настройки не меняются.

## Настройки

```json
{
  "update": {
    "checkOnStart": true,
    "intervalHours": 6,
    "autoDownload": true
  },
  "notify": {
    "enabled": true,
    "targets": "admin"
  }
}
```

| Поле | Значение | По умолчанию |
|---|---|---|
| `update.checkOnStart` | проверять при старте | `true` |
| `update.intervalHours` | интервал, 1–168 ч | `6` |
| `update.autoDownload` | скачивать найденный bundle в фоне (не устанавливает) | `true` |
| `notify.enabled` | уведомления о жизненном цикле в чат | `true` |
| `notify.targets` | `"admin"` (первый админ), `"all"` (все допущенные) или массив chat id | `"admin"` |

## API

| Метод | Путь | Действие |
|---|---|---|
| POST | `/api/update/check` | Проверить GitHub и обновить кэш |
| POST | `/api/update/download` | Запустить фоновую загрузку и сразу ответить |
| POST | `/api/update/cancel` | Отменить загрузку (`.part` остаётся для продолжения) |
| POST | `/api/update/install` | Распаковать, заменить и перезапустить |
| POST | `/api/update/rollback` | Вернуть `{app}\prev` и перезапустить |
| GET | `/api/changelog?from=X&to=Y` | Разделы CHANGELOG в `(X, Y]` |

`/api/state` содержит `update.prevVersion`, `update.bundled`, `update.verified`,
`update.paused`, `update.progress`, `update.error`, `update.errorCode` и
`update.errorStatus`.

## Панель и трей

В панели одна кнопка: «Скачать и установить», пока bundle нет; «Скачивание… N %»
и «Отмена» при загрузке; «Установить», когда bundle скачан и SHA256 проверен;
«Установка…», пока стартует помощник. После ошибки — «Повторить», причина под
баннером и ссылка «Страница релиза» на нужный релиз GitHub.

Трей повторяет это: «Скачать и установить X» (загрузка и установка без
диалогов), «Отменить загрузку» при загрузке, «Повторить» / «Открыть страницу
релиза» при ошибке; подсказка трея показывает процент. После успешной установки
приложение перезапускается сразу, без вопроса «перезапустить сейчас?».

## Окно CHANGELOG (Electron)

После обновления, если `prevVersion < current`, оболочка открывает модальное окно
со всеми разделами CHANGELOG в `(prev, current]`, с прокруткой и кнопкой
«Понятно». Показ один раз на версию: подтверждённая версия хранится в
`ui.seenChangelog`. Пункт трея «Что нового» открывает текущую версию вручную.

## Трей и CLI

- Трей: «Проверить обновления», «Скачать и установить X», «Откатиться на X», «Что нового».
- CLI:

```
ocbridge-cli update --check
ocbridge-cli update --install
ocbridge-cli update --rollback
```

## Релизный пайплайн

Каждый релиз должен содержать:

- `ocbridge-bundle-<version>.zip` + `.sha256`
- `ocbridge-setup-standalone-<version>.exe` + `.sha256` (полный, всё внутри)
- `ocbridge-setup-lite-<version>.exe` + `.sha256` (скачивает bundle)

`scripts/build-release.ps1` собирает всё; см.
[build-and-release.md](build-and-release.md).
